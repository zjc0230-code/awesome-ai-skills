# 项目介绍文档写作规范

本文件提供项目介绍文档的专门写作规范，应与基础规范（SKILL.md）结合使用。

**参考资料**：根据项目文档写作最佳实践和行业标准整理而成。

## 适用范围

编写或编辑以下类型的项目介绍文档时使用此规范：
- 项目 README 文档
- 项目概述文档
- 项目方案文档
- 项目总结文档
- 项目汇报文档

## 文档结构规范

### 基本结构

项目介绍文档应包含以下核心模块：

1. **项目概述**：项目背景、目标、价值
2. **项目功能**：核心功能、特性说明
3. **技术架构**：技术选型、系统设计
4. **项目成果**：实现效果、数据指标
5. **使用说明**：快速上手、使用指南（可选）
6. **后续规划**：未来计划、优化方向（可选）

### 模块详细要求

#### 项目概述

- **背景说明**：1-2 段说明项目产生的背景和原因
- **项目目标**：明确项目要达到的目标
- **项目价值**：阐述项目的意义和价值

#### 项目功能

- 使用列表列举核心功能
- 每个功能简要说明作用
- 重要功能可详细描述
- 配合截图或流程图

#### 技术架构

- **技术栈**：列举使用的主要技术
- **架构设计**：说明系统整体架构
- **核心模块**：介绍主要模块和作用
- 配合架构图或模块图

#### 项目成果

- **功能成果**：实现的主要功能
- **性能指标**：关键性能数据
- **业务价值**：对业务的贡献
- 量化成果，使用具体数据

#### 使用说明

- **环境要求**：列出必备的环境和依赖
- **快速开始**：提供快速上手的步骤
- **配置说明**：说明主要配置项
- **常见问题**：解答常见问题（可选）

#### 后续规划

- **优化计划**：计划进行的优化
- **功能扩展**：计划添加的功能
- **技术升级**：计划的技术升级

## 内容写作规范

### 项目概述写作

#### 背景说明

使用"背景 + 问题 + 解决"的结构：

```
背景：在日常工作中，我们发现...

问题：当前系统存在...问题，导致...

解决：为了解决这个问题，我们开发了...
```

#### 项目目标

目标应具体、可衡量：

- **功能目标**：实现哪些功能
- **性能目标**：达到哪些性能指标
- **业务目标**：达成哪些业务价值

**示例**：

```
项目目标：
- 实现自动化部署流程，将部署时间从 2 小时缩短到 10 分钟
- 支持并发用户 1000+，系统响应时间 < 100ms
- 降低运维成本 30%
```

#### 项目价值

从多个角度阐述价值：

- **效率提升**：提升了多少效率
- **成本降低**：降低了多少成本
- **体验改善**：改善了哪些体验
- **技术创新**：有哪些技术创新

### 功能介绍写作

#### 功能列举

使用"功能名称 + 功能描述"的结构：

```
核心功能：

1. 用户管理
   提供用户的创建、编辑、删除等功能，支持角色和权限管理。

2. 订单处理
   支持订单的创建、支付、发货、退款等全流程管理。
```

#### 功能分类

将功能按模块分类：

```
用户模块：
- 注册登录
- 个人信息管理
- 权限管理

订单模块：
- 订单创建
- 订单支付
- 订单查询

...
```

### 技术架构写作

#### 技术栈列表

分类列举技术：

```
后端技术：
- Java 17
- Spring Boot 3.0
- MyBatis Plus
- MySQL 8.0

前端技术：
- React 18
- TypeScript
- Tailwind CSS

中间件：
- Redis 7.0
- Kafka 2.8
- Elasticsearch 8.0
```

#### 架构设计

- 说明整体架构类型（如：微服务架构、分层架构）
- 介绍各层的作用和关系
- 重点描述核心设计思想

**示例**：

```
本系统采用分层架构设计，分为表现层、业务逻辑层、数据访问层：

- 表现层：负责用户交互，使用 React 框架实现
- 业务逻辑层：实现业务逻辑，使用 Spring Boot
- 数据访问层：与数据库交互，使用 MyBatis Plus

系统采用前后端分离架构，通过 RESTful API 进行通信。
```

### 项目成果写作

#### 量化成果

使用具体数据说明成果：

```
性能成果：
- 系统支持并发用户 5000+
- 平均响应时间 50ms
- 99.9% 的请求在 200ms 内完成

业务成果：
- 月活跃用户增长 50%
- 用户留存率提升 20%
- 客单价提高 15%
```

#### 对比说明

使用改进前后的对比说明效果：

```
改进前：
- 部署时间：2 小时
- 故障率：0.1%
- 运维成本：10 万/月

改进后：
- 部署时间：10 分钟（减少 91.7%）
- 故障率：0.01%（降低 90%）
- 运维成本：7 万/月（降低 30%）
```

## 格式规范

### 标题使用

- 使用二级标题划分主要模块
- 使用三级标题细化内容
- 标题简洁明确，不超过 15 字

### 列表使用

- 使用项目符号列举功能、技术等
- 每个列表项独立成行
- 重要信息加粗

### 数据展示

- 使用表格展示对比数据
- 使用百分比表示增长率
- 使用图标或符号标识重要数据

**示例**：

| 指标 | 改进前 | 改进后 | 提升幅度 |
|-----|--------|--------|---------|
| 响应时间 | 200ms | 50ms | 75% ⬇️ |
| 并发用户 | 500 | 2000 | 300% ⬆️ |
| 故障率 | 0.1% | 0.01% | 90% ⬇️ |

### 图表使用

- 架构图：展示系统架构和模块关系
- 流程图：展示业务流程和数据流向
- 截图：展示界面和功能效果
- 图表下方添加说明文字

## 文档风格

### 语言风格

- 专业准确
- 简洁明了
- 客观中正
- 避免主观评价

### 读者导向

- 明确读者是谁（技术人员、管理人员等）
- 根据读者调整内容深度
- 技术文档提供足够技术细节
- 汇报文档突出成果和价值

### 价值导向

- 突出项目的价值和成果
- 量化项目的贡献和影响
- 说明对业务的支持和帮助

## 不同类型文档

### 项目 README

- 包含项目简介、安装、使用、贡献指南
- 提供清晰的使用说明
- 包含示例代码
- 提供 LICENSE 和联系方式

### 项目方案

- 详细说明项目计划和实施方案
- 包含时间、资源、风险等要素
- 分阶段说明实施步骤
- 提供进度和里程碑

### 项目总结

- 总结项目完成情况
- 分析经验教训
- 提出改进建议
- 归档项目资料

## 质量检查

发布前检查以下要点：

- [ ] 项目概述清晰完整
- [ ] 功能描述准确无误
- [ ] 技术架构说明清楚
- [ ] 成果数据真实可靠
- [ ] 格式规范排版美观
- [ ] 无错别字和语法错误
- [ ] 图表清晰准确
- [ ] 参考资料完整

## 注意事项

### 真实性

- 所有数据真实可靠
- 避免夸大和虚假表述
- 成果应有数据支撑

### 完整性

- 核心信息完整
- 不遗漏重要内容
- 技术细节充分

### 可维护性

- 文档结构清晰
- 便于后续更新
- 内容模块化

### 时效性

- 及时更新文档
- 标注版本和时间
- 定期检查过时信息
